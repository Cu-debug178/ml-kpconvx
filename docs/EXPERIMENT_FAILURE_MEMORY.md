# 实验失败记忆：队列、配置和产物校验

这是一份可迁移到其他训练/评估项目的运行经验。它记录的是失败模式和防护规则，
不是某一台机器或某个模型的临时操作手册。

## 2026-08-13 事故摘要

GLSKF B1 长训已经产生了完整的 180 轮验证、current/best checkpoint 和 10-vote
产物。后处理队列有三个工程失败：

1. baseline job 的 shell 文件没有执行权限，队列得到 exit `126`。
2. 实验报告使用公开标签 `shuffled`，模型配置只接受内部枚举 `shuffle`，运行时抛出
   `ValueError`。
3. summary 依赖前两项，因缺少 baseline/shuffled 的完整 `result.json` 而失败；依赖
   检查正确阻止了 DKS 预检使用不完整或旧的上游结果。

修复后，队列保留已有成功项，只补跑失败项，生成了完整 GLSKF summary，并继续进入
DKS 预检。这个过程说明：事故是启动和接口契约错误，不是训练权重损坏，也不是模型
指标结论。

同日 DKS Phase-A 又出现两类可迁移的运行事故：

1. 宿主/容器环境在 `fixed_0.8` 运行到验证中途后重启。进程消失、日志停在第 4 次
   验证、只有 3 行验证记录且没有 success marker；退出原因无法从现有证据判定为
   OOM、驱动故障或外部终止。半成品被带时间戳归档，正式任务从同一 L0 checkpoint
   重新开始，不能拼接半成品或覆盖原目录。
2. GPU 恢复后误用另一 Python 环境，`torch` 可导入但缺少 `easydict`，导致任务在
   import 阶段失败、GPU 空闲并触发连续失败熔断。这不是模型失败。队列启动前应锁定
   已验证解释器，检查关键依赖和 CUDA；失败记录要区分“环境启动失败”和“训练失败”。

这两类事故共同说明：恢复训练时必须核对解释器路径、依赖版本、CUDA 可用性、完整
产物和 success marker；“GPU 已出现”不等于“实验环境已可运行”。

## 可复用的根因模式

### 1. 进程结束不等于任务完成

PID 消失只能说明进程退出。PID 可能被复用，`/proc` 读取也可能处于竞态。完成状态
必须由以下证据决定：

- 记录并复核 PID 的 start ticks 和命令行；
- 检查退出码；
- 检查完整验证行数、current/best checkpoint、summary 和 success marker；
- 检查产物是否属于本次 seed、checkpoint、协议和配置，而不是旧目录中的同名文件。

### 2. 公开标签和内部枚举容易漂移

报告标签可能为了可读性使用 `shuffled`，模型内部为了简洁使用 `shuffle`。这类边界
必须显式建立单向映射，不能把用户输入直接写入配置。所有公开标签都应有：

- canonical mapping；
- 未知标签的早期报错；
- 每个别名到内部值的单元测试；
- 最终解析配置的记录。

### 3. 默认配置可能覆盖干预配置

数据集或验证模式初始化函数可能重新写入模型字段。干预参数应在所有默认配置函数
执行完后最后应用，并对最终配置做断言或写入 `run_config.json`。只测试“调用过配置
函数”不够，要测试最终网络实际收到的配置。

### 4. shell 文件元数据是运行时依赖

脚本内容正确并不代表可执行。队列生成或提交前应检查：文件存在、可读、解释器可用、
`bash -n` 通过、执行权限符合约定。若队列明确要求可执行文件，权限错误应被记录为
独立 job 失败；重跑时只能跳过有完整 success marker 的任务。

### 5. 依赖队列必须以新鲜产物为门槛

独立任务失败可以继续，但依赖任务不能使用 stale 输出。上游应写入原子 success
marker，并把 seed、checkpoint 内容哈希、协议和配置摘要写入产物。下游启动前验证
这些字段和所需文件；失败时写 failure marker 和日志，而不是猜测状态。

### 6. 重试和 circuit breaker 要区分局部失败与系统性失败

- 独立任务：记录每次 attempt、退出码、日志、GPU/内存/磁盘快照，然后继续后续任务；
- 连续相同类型失败达到阈值：停止队列，避免重复烧费；
- 依赖流水线：上游失败则标记下游 skipped；
- 重跑：跳过已验证成功项，保留失败目录，不覆盖诊断证据。

## 提交前检查清单

```text
[ ] 所有 job 文件存在、可读、权限正确，bash -n 通过
[ ] 公开实验标签都有内部枚举映射和单元测试
[ ] 默认配置完成后再应用实验干预
[ ] 记录 seed、checkpoint/hash、协议和最终解析配置
[ ] 用退出码 + 完整产物判定成功，不用 PID 消失判定成功
[ ] 下游只接受本次运行的 success marker 和完整产物
[ ] 失败任务保留日志和资源快照，重跑不覆盖失败目录
[ ] 连续系统性失败触发 circuit breaker
```

## 适用边界

这些规则适用于无人值守的训练、验证、消融和多阶段实验队列。它们不能替代模型
统计设计：单 seed、checkpoint 选择偏差、测试集复用和协议不一致仍需在实验报告中
单独披露。一个队列运行成功，也不等于模块带来性能收益。
